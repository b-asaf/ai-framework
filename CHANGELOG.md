# Changelog

All notable changes to ai-framework are documented here.
Format: [version] — [date] — [summary]

Changes are made on `develop` branch and merged to `main` when stable.

---

## Unreleased (develop)

- **Removed `opencode-usage` and `monitoring/model-policy-check.js`.** The
  policy check was the only consumer of `opencode-usage` data, and
  `opencode-usage` was the only reason that dependency existed — removing
  both together, not deprecating one and orphaning the other.
  `install_opencode_usage()` and its call site/verify-mode check are gone
  from `setup.py`; `ccusage` (cross-tool token/cost dashboard) is unaffected
  and remains the framework's monitoring tool — see `monitoring/README.md`.
  If per-agent model-policy enforcement is wanted again later, it needs a
  different data source: `opencode-usage` installs hit a hard TLS-trust wall
  on networks with corporate TLS-inspection proxies (`uv`'s bundled
  cert store doesn't trust an intercepting proxy's CA by default), which is
  what surfaced this dependency was worth cutting rather than working around.

## v1.8.0 — critical CRLF fix, folder reorg, graphify sync gaps closed

- **Critical: every file touched since v1.5.0 had been silently corrupted
  to CRLF line endings** (almost certainly a Windows-based merge with
  `core.autocrlf`). Verified this wasn't cosmetic — `hooks/pre-push`,
  `hooks/install-hooks.sh`, and `build-verify.sh` were actually broken,
  failing with `\r: not found` and syntax errors when run. This means the
  structural push-gate enforcement from v1.6.0 was likely non-functional
  since it landed. Normalized every affected file back to LF and verified
  each script parses and runs again.
- **Added `.gitattributes`** — enforces LF for `.sh`/`.py`/`.md`/`.json`
  and the extension-less hook files, regardless of contributor OS. Root
  cause fix, not just a one-time cleanup — prevents this from recurring.
- **`.gitignore`** — added `/git-template/` (generated by `setup.py`,
  possibly machine-specific — was never ignored, so it was one `git add -A`
  away from getting committed) and `__pycache__/`/`*.pyc`.
- **Folder reorg**: moved `scripts/hooks/build-verify.sh` → `hooks/build-verify.sh`
  (co-located with `pre-push`, which is the only thing that uses it — the
  nested nested `scripts/hooks/` location added a folder for no reason) and
  `scripts/hooks/graphify-smart-viz.sh` → `scripts/graphify-smart-viz.sh`
  (it isn't a git hook at all, was only filed under "hooks" by accident of
  naming). `add_git_template()` simplified accordingly — `build-verify.sh`
  is now just one more entry in the existing hook-copy loop instead of a
  separate special-cased copy step. `hooks/install-hooks.sh` updated to
  install it too. Re-verified end-to-end after the move: `add_git_template()`
  run in an isolated `$HOME`, a real `git init` against the resulting
  template, and a genuinely failing test correctly blocking a real push —
  all three still pass after the reorg.
- **`skills/graphify/SKILL.md`** — was understating what `graphify hook
  install` actually wires (it's post-commit **and** post-checkout, not
  commit-only) and never instructed committing `graphify-out/` to git —
  without that, `git pull` never propagates a fresh graph, since there's no
  hook for "someone else's commits arrived." Both fixed; `first-run-analysis`
  Step 7 now commits the initial graph alongside `.ai-framework.json`.
- All content changes from v1.5.0–v1.7.1 were verified byte-identical once
  CRLF was stripped — nothing was actually lost in the earlier corruption,
  only line endings.

## v1.7.1 — same Windows-path bug fixed in a second installer

- **`install_opencode_usage()`** had the identical Windows-unsafe pattern
  CodeRabbit fixed in `install_graphify` (`installer.endswith("uv")`,
  which is `False` for a real Windows path like `uv.exe` since it's a
  substring match, not a filename match) — never caught because it was
  outside the scope of the graphify work. Fixed to the same
  `Path(installer).name.lower()` pattern already used in `install_graphify`,
  plus added the same missing post-install verification (`opencode-usage`
  resolvable on PATH after install, not just assumed from a zero exit code).
  Swept the rest of `setup.py`'s installers (`install_rtk`,
  `install_token_optimizer`, `install_ccusage`) — none share this pattern.

## v1.7.0 — trimmed build-verify output, API-key references fully swept

- **`scripts/hooks/build-verify.sh`** — failing-stage output is now trimmed
  to the last ~40 lines by default (`--trim-lines N` to override), instead
  of dumping a full test-suite log back into the agent's context on every
  retry. Full output is always written to `.git/build-verify-logs/<stage>.log`
  regardless, and the path is printed — `--full` shows it inline instead of
  trimmed. Verified: a 101-line noisy failure trims to 46 total lines by
  default, `--full` returns all of it, the log file always retains the
  complete output.
- **`skills/build-verify/SKILL.md`** — updated to use the trimmed tail for
  normal retries, and only pull `--full` output once, for the 3rd-failure
  escalation report — matches the "same session ID, don't re-derive context
  every retry" principle without also re-injecting full noise every retry.
- **CHANGELOG.md** — reworded the v1.3.0 entry to describe the removed
  script's requirement without repeating the literal env var name. Full
  repo sweep confirms no remaining file, folder, or doc references or
  requires an Anthropic API key anywhere.

## v1.6.0 — build-verify enforced structurally, not just by instruction

- **Fixed a pre-existing bug in `add_git_template()`** — the git template
  directory was created but never populated with the actual hook scripts,
  so `init.templateDir` had nothing to apply; every new repo silently got
  no hooks at all. Now copies `pre-commit`/`commit-msg`/`pre-push` (and
  `build-verify.sh`) into the template on every `python setup.py` run.
- **Fixed a second pre-existing bug in `hooks/install-hooks.sh`** — pointed
  at `scripts/hooks/` for source files that actually live in `hooks/`,
  so it always printed "not found — skipped" for all 3 hooks regardless
  of context.
- **`hooks/pre-push` now runs `build-verify` structurally**, after the
  existing branch-protection check. This is the actual point of this
  release: the agent-side loop added in v1.5.0 was still instruction-level
  (an agent is told to run it and trusted to report honestly). This hook
  is not — it runs on the human's real `git push`, outside any agent's
  control, reading commands from `.ai-framework.json` at the project's
  own repo root. Missing file/commands → skipped with a note (doesn't
  block projects that haven't run first-run analysis yet). Escape hatch
  for emergencies: `SKIP_BUILD_VERIFY=1 git push` (branch protection still
  applies regardless).
- **`first-run-analysis`** now writes `.ai-framework.json` per repo
  alongside `stack.md`, from the same detection pass — one source of
  truth for both the human-readable commands in `stack.md` and the
  machine-readable ones the hook reads.
- **`skills/build-verify/SKILL.md`** — documents both layers explicitly:
  agent-side loop for fast feedback, git hook for actual enforcement.
- **README** — new Check 6 ("the push gate is actually enforced, not just
  instructed") verifies this without involving the AI tool at all.

## v1.5.0 — separated builder from self-correction (build-verify)

- **Added `skills/build-verify/SKILL.md`** and **`scripts/hooks/build-verify.sh`**
  — a deterministic lint → format → test gate for implementation agents,
  separate from the agent that writes the code. Pass/fail comes from the
  actual exit code, never the builder's own read of its output — same
  reasoning as why `code-reviewer` doesn't let an agent review its own PR,
  applied one step earlier in the loop.
- **Bounded retries with mandatory escalation**: 3 attempts per stage, then
  stop and report to the developer with the raw output from all 3 attempts
  — no silent 4th retry. A capped loop that escalates honestly beats an
  uncapped loop that burns tokens hoping to get lucky.
- **Wired into `backend`, `frontend`, `frontend-error-fixer`, `api`, `db`,
  `ui`** — each now loads `build-verify`, has a narrow permission grant for
  `scripts/hooks/build-verify.sh` (so the loop doesn't hit a confirmation
  prompt on every retry), and runs it before declaring work done, replacing
  each agent's previous ad hoc "run the linter"/"confirm the build passes"
  instruction.
- **`code-reviewer`'s Stage 1** now documented as a safety net rather than
  the primary lint gate — by the time review starts, build-verify should
  already have passed.
- **`project-overview/sub/stack.md`** — added explicit Lint/Format/Test
  command fields (exact runnable commands, not just tool names), since
  build-verify needs something it can literally execute.
  `first-run-analysis`'s detection tables updated to populate them.

## v1.4.0 — review output grouped by file, review someone else's branch documented

- **`agents/code-reviewer.md`** — output format restructured to group
  findings by file, then by line, instead of by severity category. Reads
  like inline PR review comments anchored to their location instead of a
  flat blocking/non-blocking list.
- **Optional inline GitHub PR comments** — documented, not automatic.
  `code-reviewer` remains read-only; posting through `gh pr review`/`gh api`
  only happens if you ask for it after `/review` finishes, and goes through
  the agent's existing `"*": ask` permission gate (confirmation required).
- **`README.md`** — documented reviewing a colleague's pushed branch
  (`git fetch` + `git checkout -b <branch> origin/<branch>` + `/review`,
  same as your own branch since the diff is always taken against the
  protected base, not your local history).

## v1.3.0 — removed `ci/review.js`

- **Removed `ci/` entirely** (`ci/review.js`, `ci/README.md`). It was the
  only thing in the framework requiring a separate Anthropic API account and
  billing — a headless script calling the raw Messages API directly for CI
  pipelines with no interactive session. Superseded by documenting `/review`
  properly instead: it runs the identical checklist (same skills, same
  agents) from your existing Claude Code/OpenCode session, with no separate
  key or account.
- **`README.md`** — added step-by-step `/review` usage under "Everything you
  can trigger manually" (branch you should be on, commit-before-review,
  same-session-or-new, how the diff base is determined).
- If you need unattended CI review without an API key, see Anthropic's
  official `claude-code-action` (OAuth token via `claude setup-token`,
  Pro/Max subscribers) — not wired into this framework, evaluate
  independently before adopting since OAuth billing behavior in CI has open
  reports as of early 2026.

## v1.2.0 — Graphify integration

- **Added Graphify** (`skills/graphify/SKILL.md`) — local, deterministic
  code knowledge graph (tree-sitter AST, zero LLM cost for code). Agents
  query it (`graphify query`/`graphify path`/`graphify explain`) instead of
  reading files one by one to figure out structure.
- **Wired into `setup.py`** (`install_graphify`/`wire_graphify`) — installs
  the CLI via `uv`/`pipx` and registers the skill globally, alongside
  RTK/Token Optimizer in the "Token usage reduction" section of `README.md`.
  Two steps remain per-project (not global, run once inside each opened
  repo): `graphify <platform> install` (always-on nudge) and
  `graphify hook install` (keeps `graphify-out/graph.json` current on
  commit).
- **`scripts/hooks/graphify-smart-viz.sh`** — auto-skips `graph.html`
  generation past ~5000 nodes (configurable via `GRAPHIFY_VIZ_NODE_LIMIT`),
  since the visualization becomes unusable at that size; `GRAPH_REPORT.md`
  and `graph.json` are still generated regardless of size.
- **`zoom-out` / `first-run-analysis`** — both now prefer the graph over a
  manual read sequence / file sampling when it's available, falling back to
  the original behavior otherwise.

## v1.1.0 — agent consolidation, monitoring, install reliability

- **Added cross-tool token monitoring (`ccusage`).** Wired into `setup.py`
  (`install_ccusage`) alongside `opencode-usage` (`install_opencode_usage`),
  not replacing it — they answer different questions. `ccusage` reads local
  usage logs from Claude Code, Codex CLI, OpenCode, Gemini CLI, and Copilot
  CLI, giving one command family (`ccusage daily/weekly/monthly/session`)
  across whichever tool a developer actually used that day. `opencode-usage`
  stays as the engine behind `monitoring/model-policy-check.js`: it's the
  only one that reads OpenCode's own per-agent metadata — `ccusage`'s
  `agent` field means "which coding tool," not "which OpenCode subagent"
  (verified against ccusage's actual `--json` output before wiring; these
  were initially assumed interchangeable, corrected before implementing).
  Known gap, documented in `monitoring/README.md`: `ccusage`'s Copilot
  support covers the Copilot CLI, not the IntelliJ/VS Code IDE extensions
  this framework also wires into.
- **Added `monitoring/model-policy-check.js`** — cross-references actual
  per-agent model usage against each agent's own `model:` frontmatter
  declaration (no separate policy table to keep in sync). Tested end-to-end
  against a mocked `opencode-usage` output including a deliberate mismatch
  case; correctly flagged it and cleared the rest.
- **Added `ci/review.js`** — headless CI code-review runner (Stage 1:
  prints a structured verdict to stdout + a log file; hand-paste into your
  PR/MR for now). Runs the same checklist as `agents/code-reviewer.md`,
  loading its declared skills directly rather than reimplementing them, with
  one addition: checklist items that assume a spec/HLD from the interactive
  `/task` flow are explicitly treated as N/A in headless mode instead of
  failing. No `@gatekeeper` step (validates against task-flow state that
  doesn't exist for an arbitrary PR) and no branch guard (nothing to guard
  in CI). Zero npm dependencies — native `fetch`, Node 18+. Stage 2
  (auto-post via `gh pr comment` / GitLab's notes API) sketched at the
  bottom of the file, not wired yet.

- **Dropped Cursor and Windsurf support.** They were never actually wired by
  `setup.py` (not in `detect()` or `build_links()` at all) — `CURSOR.md` and
  `WINDSURF.md` were dead files nothing ever installed. Deleted both, along
  with `SHARED.md`/`SHARED-reference.md` (their only real consumers besides
  an also-unused `instructions/wrappers/` folder — every live tool integration
  already points straight at root `AGENTS.md`/`AGENTS-reference.md`). Net:
  4 files + 1 folder removed, zero functional change, one less place for
  rules to silently drift out of sync (this is what caused the linter
  references to go stale in `SHARED.md` before being caught above).

- **Agent consolidation:** merged `linter` into `code-reviewer` (16 → 15 agents).
  `code-reviewer` now runs lint/security detection as Stage 1, then review as
  Stage 2, in one pass — removes a duplicate `static-code-analysis` invocation
  that both agents were separately running. Updated: `orchestrator.md` (Steps
  6-7 merged), `gatekeeper.md`, `AGENTS.md` Rule 9, `AGENTS-reference.md`,
  `SHARED.md`/`SHARED-reference.md`, `commands/review.md`, `commands/task.md`,
  `CURSOR.md`, `WINDSURF.md`, and the skills that referenced the linter agent
  by name (`static-code-analysis`, `linting-tools`, `xray-scanning`, `caveman`,
  `project-overview/sub/tooling.md`). Tradeoff: lint/security scanning now runs
  on `code-reviewer`'s Sonnet tier instead of the old Haiku-tier `linter` —
  fewer agent hops, slightly higher per-PR cost on that step.
- **Fixed double skill-routing:** `skill-rules.json` (fuzzy keyword/intent
  matching) and each agent's own hardcoded "Always load" list were both firing
  inside the structured task flow, stacking skills on top of each other.
  `skill-rules.json` is now explicitly scoped to ad-hoc/off-workflow requests
  only (AGENTS.md/SHARED.md Rule 8 rewritten); inside `/task`, each agent's own
  list is sole authority. Added `$config.maxMatchesPerRequest: 3` (priority-
  ordered cutoff) to `skill-rules.json` for the ad-hoc case.
- **Removed the redundant task-type skill-routing table** from
  `AGENTS-reference.md` and `SHARED-reference.md` — it duplicated
  `skill-rules.json` (which itself says it was meant to replace that table;
  the replacement was never finished until now).
- **Removed Headroom** — dropped from the token-reduction stack (now RTK +
  Token Optimizer only). Removed `install_headroom()`/`wire_headroom()` from
  `setup.py`, its row from the README token-reduction table, and its
  troubleshooting entry.
- **`setup.py` no longer requires admin rights / UAC elevation.** Removed
  `_enable_developer_mode_windows()` (registry write + UAC-elevated
  PowerShell attempt) — corporate/locked-down machines were failing exactly
  where this ran. File symlinks silently fall back to copies as before; the
  script no longer tries to fix that itself.
- **`gh` CLI: detect-only, no auto-install.** Removed the `brew`/`winget`
  install attempts (`install_gh()` → `check_gh()`) — same reasoning as above.
  The framework already degrades gracefully without `gh` (AGENTS.md Check 4:
  push, then open the PR manually).
- **Added `python setup.py --verify`** — read-only status check (symlink/copy
  drift via content hash, `gh` presence) that can be re-run anytime without
  touching any files.
- **Added a single "Action required" summary block** at the end of setup
  output — anything the developer needs to do themselves (missing `gh`,
  no symlink privilege, stale copies) is now collected and printed once,
  instead of scattered mid-log warnings that were easy to miss.
- Deleted `enable-dev-mode.ps1` (dead file, no longer called).
- Per-agent model tiers (Opus/Sonnet/Haiku based on task complexity)
- Token monitoring: opencode-tokenscope, opencode-usage wired via setup.py
- Guarded commit/push/PR flow (Check 4 in AGENTS.md)
- Rule 14: auto-trigger caveman + handoff at context budget threshold
- 8 skills set to disable-model-invocation: true
- Quick reference sections on all skills > 40 lines
- All agents load project-overview sub-files selectively
- Token reduction stack: RTK + Token Optimizer
